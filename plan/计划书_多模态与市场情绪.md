## 1. Docker 可用性核查（结论）

**结论：Docker 已安装但 daemon 未运行，本方案不使用 Docker。**

- `docker --version` → Docker 29.4.1（CLI 就绪）
- `docker ps` → 失败：`npipe:////./pipe/dockerDesktopLinuxEngine` 连接失败，**Docker Desktop Linux 引擎未启动**

## 2. 多模态接入方案（图片 / 音频 / 视频）

### 2.1 架构

新增 `app/multimodal/` 子包，作为「多模态 → 文本 → 现有 LLM 客户端」的预处理层。

```
用户上传 (图/音/视) ──> app/multimodal/ingest ──> 结构化文本
                       ├ image.py  图片: OCR文字（paddleocr；视觉模型暂缓）
                       ├ audio.py  音频: faster-whisper 转写
                       └ video.py  视频: 抽关键帧(→image) + 抽音轨(→audio)
                              │
                              ▼
                    {kind, text, meta, sources}
                              │
                              ▼
           现有 DeepSeek 客户端（只吃文本，不改 client.py）
```

**关键点**：DeepSeek 官方 API 不支持视觉输入（2026-08 确认，Anthropic 兼容端点拒绝 image 块），因此所有多模态内容在本地预处理为文本，再喂给现有 LLM。**不改 `app/llm/client.py`**。

### 2.2 图片识别 `app/multimodal/image.py`

- **文字提取**：`easyocr`（已装，中文识别已验证，零新依赖）→ 返回带坐标/置信度的文本。**引擎变更说明**：paddleocr 3.5 需新装 paddlepaddle(~200MB)，磁盘受限下改用本机已装的 easyocr（torch 已装）；若未来想要更快的 onnx 方案可换 rapidocr_onnxruntime（约 10MB 小装）
- **视觉语义（暂缓）**：Ollama Qwen2.5-VL 因磁盘空间不足不加（用户确认）。未来 `ollama pull qwen2.5-vl:7b`（约 5GB）后可启用，届时输出加 `vision` 字段，无需改动其余管线
- 输出：`{kind:"image", text: OCR行文, vision: None, source: "easyocr", as_of}`

### 2.3 音频转写 `app/multimodal/audio.py`

- `faster-whisper`（需安装）+ 本地模型 `whisper small`（中文准确）/`base`（更轻，默认 base，可配）
- 音频解码：`av`(PyAV) 优先，缺 → `imageio-ffmpeg` 兜底（ffmpeg 不在 PATH）
- 输出：`{kind:"audio", text: 逐段转写(带时间戳), duration_sec, language, source:"faster-whisper", model}`

### 2.4 视频识别 `app/multimodal/video.py`

- **抽关键帧**：`opencv`（已装）按固定间隔抽帧 + 场景变化检测，帧 → `image.py`（OCR，视觉模型暂缓）
- **抽音轨**：PyAV 解音轨 → `audio.py` 转写
- 输出：`{kind:"video", text: 音轨转写, frames: [{ts, ocr}], source:["opencv","faster-whisper"]}`

### 2.5 统一入口 `app/multimodal/ingest.py`

```python
def ingest_bytes(data: bytes, filename: str) -> dict:
    ext → kind（png/jpg=image, mp3/wav/m4a=audio, mp4/avi/mov=video）
    分发到 image/audio/video 处理器
    缺依赖（如 faster-whisper 未装）→ 返回 {error, hint}，绝不静默编造
```

### 2.6 接入点

- **API**：`POST /api/v1/multimodal/ingest`（multipart 上传）→ 返回结构化文本 + 元数据
- **看板**：AI 对话页（`ui/pages/chat.py`）新增「📎 上传图/音/视频」按钮 → 调 ingest → 将结果文本拼入对话上下文，用户可追问
- **模型路由**：多模态任务不占 MODEL_TIERS（本地处理，非 LLM 调用）；只有「情绪解读/总结」走现有 LLM

### 2.7 依赖安装（`D:\python\python.exe`）

| 包 | 用途 | 现状 |
|---|---|---|
| easyocr（torch 已装） | OCR（中文） | ✅ 已装 |
| opencv-python | 视频抽帧 | ✅ 已装 |
| faster-whisper | 音频转写 | ❌ 需安装 |
| av 或 imageio-ffmpeg | 音频解码（ffmpeg 不在 PATH） | ❌ 需安装 |

> 注：Ollama 0.32.11 已装但**视觉模型 qwen2.5-vl 暂缓拉取**（磁盘空间不足），图片仅走 OCR，零额外空间。OCR 引擎因 paddleocr 3.5 需 paddlepaddle(~200MB) 改用已装 easyocr。

## 3. 市场情绪 AI（A股 / 美股 / 港股）

### 3.1 目标

对三大市场输出**市场级**情绪评分（非个股），多源信号合成 + LLM 解读。

### 3.2 信号源（已实测验证）

| 维度 | A股 | 美股 | 港股 |
|---|---|---|---|
| 指数动量 | 沪深300/中证1000 历史 | 标普500 `index_us_stock_sina` ✅ | 恒指 `stock_hk_index_daily_sina` ✅ |
| 涨跌广度 | 涨停/跌停池 `stock_zt_pool_em` ✅ | 涨跌家数（东财美股） | 恒指成分涨跌（akshare） |
| 资金流 | 北向 `stock_hsgt_hist_em` ✅、两融 `stock_margin_sse` ✅ | — | 南向资金 `stock_hsgt_hist_em(港股通沪)` ✅ |
| 恐慌/贪婪 | QVIX（上证50ETF期权中国波指） | VIX（**CBOE 官方 CSV**，本环境东财/Sina VIX 均不可用） | 恒指 20日实现波动率（派生） |
| 舆情 | 新闻关键词+LLM（复用 `sentiment.py` 思路扩展） | yfinance news（现有） | 东财港股新闻 |

> 诚实边界：任一信号取不到 → `None` 并标注，评分仅基于可用信号；绝不补造数值（红线 #7）。

### 3.3 评分模型 `app/analysis/market_sentiment.py`

- 各信号归一化到 `[-100, +100]`（动量用历史分位、资金流用阈值映射、广度用涨跌家数比、VIX 反向映射）
- 加权合成 → 每市场总分 + 分维度 breakdown
- 标签映射：`≤-50 恐慌 / ≤-20 谨慎 / 中性 / ≥+20 偏暖 / ≥+50 贪婪`
- **LLM 解读**：把各维度数值 + 最新新闻标题喂 DeepSeek → 生成 2-3 句市场情绪解读（文本，不编数值）

### 3.4 API 与看板

- **API**：`GET /api/v1/market/sentiment?market=a_share|us|hk`（可 `all`）→ `{market, score, label, breakdown, llm_interpretation, sources, as_of}`
- **看板**：新增「🌡 市场情绪」模块页（见 §4 UI 设计）
