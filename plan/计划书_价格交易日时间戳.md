# 计划书 · 建议 3：当前值缺交易日时间戳 + pe_percentile 标注

> 建议 1/2/4/5 已落地。本计划只做 3。
> 不改历史产物、不重录 `baseline.json`、不改 L0 检查项集合、不提交 git。

**明确不做**

- 不给行情加「抓取时刻」字段——那是 `refresh.refreshed_at`，语义不同，不混用。
- 不给技术位（进场/止损/止盈/盈亏比）加 `as_of`：它们来自 60 日均线等滚动窗口，单一交易日不足以定义其「期间」。**这是本计划的已知边界**，会在计划书与代码注释里写明，不假装覆盖。
- 不改 `completeness` 的判定：老产物没有 `pricing` 属于「当时没这个字段」，不是「数据缺失」。
- 不改 L0 的检查项集合（避免动 `baseline.known_reds`）。
- 不针对早期产物做回填。

## 三、P1 · `pricing` 块（只放字符串/布尔）

```python
# app/analysis/pricing.py
def build_pricing(price_data) -> dict:
    """行情时点声明。零数值叶子：进不了台账，不改变 fact_total。"""
```

产物里长这样：

```json
"pricing": {
  "price_as_of": "2026-11-04",
  "source": "yfinance",
  "is_point_in_time": true,
  "requested_as_of": null,
  "note": "现价取该交易日收盘；当日 K 线若整行缺失（未成交）已剔除"
}
```

- `price_as_of` = 最后一个**有效收盘**所在行的日期（与 `financial.py:183-187` 取 `closes.iloc[-1]` 的口径逐字对齐，不是简单取 `index[-1]`）。
- 其余字段来自 `price_data.attrs["vintage"]`（`app/data/vintage.py` 已有，`router.get_history` 已挂）。**vintage 缺失时**：`source` 写 `""`、`requested_as_of` 写 `null`、`is_point_in_time` 写 `false`、note 追加「行情源未标注」——不猜。
- 取不到任何有效收盘 → 整个 `pricing` 块写成 `{"price_as_of": null, "note": "无有效收盘价"}`，不产出空壳日期。

为什么是顶层：现价被 `financial` / `valuation` / `trade_plan` / `sotp` 四处消费，写在任一处都会让另外三处「引用一个远处的数」。顶层一份，不重复、不会互相跑偏。

为什么全是字符串：`ledger._walk` 只把 `int/float` 落成事实，本块**不新增任何事实**，`fact_total` 不变、不新增 UNKNOWN。

## 四、P2 · 分位的样本口径

`_compute_pe_percentile` 返回值增加：

```json
"hist_pe_periods": ["2021", "2022", "2023", "2024", "2025"],
"note": "近似：股本取当前值、PE=当年均价×股本/当年净利；样本为上述年度的全年均价，仅供区间参考"
```

- `hist_pe_periods` 与 `hist_pe` 一一对应（同一次循环产出，不可能错位）。
- note 里**不写具体年份数字**（写成列表会给读者一个与 `hist_pe_periods` 可能不一致的副本），只说明口径。

## 五、P3 · 刷新时的混血问题

`refresh_price` 里：

| 字段 | 处理 |
|---|---|
| `new["pricing"]` | 用新行情重建（`price_as_of` 必等于 `refresh.effective_price_date`） |
| `valuation_context.current_pe` | 重算，并 `round(..., 2)` 与全量管线对齐 |
| `valuation_context.pe_percentile` / `hist_pe` | 保持不重算，但补 `pe_percentile_as_of = <基线日期>` |
| `refresh.carried_over` | 那条分位的 `as_of` 不变，note 改为「分位沿用 {基线日期}，现价与 PE 已按新行情重算」 |

`pe_percentile_as_of` 只在一份产物里「分位比现价旧」时才出现；全量产物里没有这个键（缺省 = 与 `pricing.price_as_of` 同日）。**缺省即同日**这条写进模块 docstring，避免下一个人误读。

## 六、P4 · 台账补 `as_of`

`build_ledger` 取 `result["pricing"]["price_as_of"]`，仅对下列路径补期间（其余一律不动）：

```python
_PRICE_ANCHORED_PATHS = frozenset({
    "financial_analysis.current_price",
    "financial_analysis.valuation_context.current_pe",
    "financial_analysis.valuation_context.pe_percentile",
    "valuation_analysis.dcf.upside",
    "trade_plan.current_price",
})
```

- 只在原 `as_of` 为空时补，不覆盖任何已有期间。
- `pe_percentile` 若带 `pe_percentile_as_of`（刷新产物），用那个日期，不用现价日期——否则等于把上个分位标成今天。
- 老产物没有 `pricing` → 行为与现在完全一致（`as_of` 仍为 `None`）。

影响面：`as_of_coverage` 会上升（204/2713 → 约 199/2713），`run_eval --baseline` 只对**下滑**报警，上升不触发漂移；`grounding` 里 `fact_years` 取最大值，仍是 2026，不变。

### 实施中被守卫抓到的问题

1. **基线产物选错会假绿/假红**：首版台账用例用了 DCF 已被倍数闸降级的产物，`dcf.upside` 根本不存在（`None` 不出事实），守卫报「as_of 不为空」失败。改为按「五条事实俱在且无 `pricing`」挑基线。
2. **第一代刷新产物无分位日期**：本改动之前生成的刷新产物既没有 `pe_percentile_as_of` 也没有 `pricing`，直接取它的现价日会把分位标新一个交易日（实测 11-04 被标成 11-06）。改为沿 `refresh.base_artifact` 回溯（≤3 层）到真正算分位的那份产物；已删掉按旧逻辑生成的那份产物并重跑。

### 已知边界

- 技术位（进场/止损/止盈/盈亏比）**不给** `as_of`：来自 60 日均线等滚动窗口，单一交易日定义不了其期间。
- 老产物（本改动前）无 `pricing`，台账行为与之前完全一致（`as_of` 仍为 `None`），不做回填。
- 刷新产物会把 `eval_l0_ledger` 的产物集合 +1（断言 168 → 180，仍只有历史 NaN 那条红）。
- **界面只做了导入/调用级验证（`_pricing_scope` / `_strategy_banner` 裸跑无异常），未在浏览器里目视确认版式**。
