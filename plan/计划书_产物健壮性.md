## 六、Step C · DCF 分母保护 + 定价背离降级（附录 P0，已修）

### 问题

`600519_SS/20261105T001635.json` 的 DCF：

- `wacc_used = 3.17%`，`terminal_growth = 3%`，分母 `wacc-g = 0.0017`；
- `fair_value = 74074.26`，`current_price = 1446.44`，`upside = +5021%`；
- 而 `valuation_analysis.summary` 仍写「DCF 内在价值 $74074.26…低估（空间 +5021.1%）」，`trade_plan` 给「强烈看多」。

根因链：基准指数 5 年年化收益为 −3.3% → ERP 夹到下限 2% → `Ke = 1.6% + 0.783×2% = 3.17%` → WACC 3.17% 几乎等于永续增长 3%。`compute_dcf` 只校验 `0 < wacc < 1`，不校验 `wacc - g` 的量级，也没校验结果与现价的偏离。

### 两道闸（`app/analysis/valuation.py`）

| 常量 / 闸门 | 位置 | 行为 |
|---|---|---|
| `MIN_WACC_GROWTH_SPREAD = 0.02` | `compute_dcf` | `wacc - g < 2pp` → `fair_value/upside=None`、`degraded=True` + reason（含实际 pp 差） |
| 同上 | `compute_sensitivity` | 矩阵的 g 轴夹到 `w - 2pp`，不再产出分母趋零的单元格 |
| `FAIR_VALUE_PRICE_BAND = (0.3, 3.0)` | `analyze()` | 每股价值/现价越界 → `fair_value/upside=None`、`degraded=True` + reason（含倍数），不再生成敏感性矩阵 |
| 同上 | `recompute_dcf_from_result` | 越界 → `{"available": False, "reason": …}`；路由层转 400，重算面板显示原因而不是 74074 |

`degraded=True` 会被台账的 `_walk` 识别为降级标记，DCF 块内所有数值叶子归 `degraded`
并带 `evidence_ref`（取自 `reason`），既不会变 UNKNOWN，也说得清为什么不用。

### 验收（实测）

| 场景 | 结果 |
|---|---|
| 复现 P0 参数（3.17% / 3%） | 拒绝：`0.17pp < 2pp` |
| `5.00% / 3%`（正好 2pp） | 放行 |
| `4.99% / 3%` | 拒绝：`1.99pp < 2pp` |
| 真实产物 `wacc=None` 重算（9%） | `available=True, fv=1946.01`（现价 1446.44，1.35 倍，合理） |
| 真实产物 `wacc=5%` 重算 | 拒绝：`6147.73` 为现价 `4.25` 倍 |
| `analyze()` 低 WACC 场景 | 拒绝：`5418.85` 为现价 `3.75` 倍；`summary` 改写为「DCF 不可用：…」；`trade_plan` 失去估值加分，不再「强烈看多」 |

> **测试夹具修正**：`scripts/verify_phase3.py` 的合成夹具现价 `8.0` 与其自身 DCF 内在价值
> `~69.5` 相差 8.7 倍，本就不自洽，被新闸门拦下。已把现价改为 `40.0`（`dcf.fair_value` 同步），
> 断言逻辑未改，41/41 通过。
