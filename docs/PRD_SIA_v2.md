## 1. 背景与问题

### 1.1 产品定位

SIA 是一个**单人使用的投研工作台**：输入标的，输出一份带财务、估值（DCF / SOTP）、竞品、SWOT、地缘、供应链与事实核查的研究报告；辅以实时行情、四大师评分、多轮对话与固收模块。

它的数据是真实的（Sina / akshare / yfinance / 东财 / SEC EDGAR / US Treasury），估值与评分是代码算的。**但「数字真实」和「读者能验证数字真实」是两件事**——本版本要解决的是后者。

### 1.2 六个缺口（基于代码核查，非推测）

| # | 缺口 | 现状证据 | 对应需求 |
|---|---|---|---|
| 1 | 研究产物质量从未被评测 | 161 个断言测的是预算/状态机/归因拒绝，不是内容质量 | FR-7、FR-8、FR-12 |
| 2 | 数字来源在产物里不可区分 | `result` 是嵌套字典，无字段标明数字是算的、取的还是模型给的 | FR-1、FR-3 |
| 3 | 三处降级被伪装成正常内容 | SWOT 失败返回「中性」评级；分部失败返回 100% 的「综合业务」并流入 SOTP；新闻失败仍置 `available=True` | FR-5、FR-6 |
| 4 | 模型产出的数字未被约束 | 分部占比 `revenue_share` 直接由 LLM 给出并进入估值 | FR-4、FR-8 |
| 5 | 插补不可见 | 前向填充/中位数插补从不进入报告 | FR-3、FR-5 |
| 6 | 数据飞轮断在第一环 | 有 `audit.db` 日志，但零反馈信号 | FR-9、FR-10 |

### 1.3 本次变更的性质

**不是加功能，是加可信度。** 用户能看到的界面几乎不变；变的是：

1. 每个数字都带出处与期间，且这个「带」是被脚本强制检查的，不是靠开发者自觉；
2. 模型产出的数字被单独隔离、可数、可度量；
3. 「降级」从静默兜底变成显式标记 + 报告可见说明；
4. 首次有了反馈入口与版本戳，飞轮第一环接通。

## 2. 用户与场景

### 2.1 使用者画像

- **单用户**：项目作者本人。既是使用者（要拿报告做判断），也是开发者（要能定位问题出在哪一层）。
- **不使用**：团队协作、机构终端多席位、对外客户。
- **前置知识**：懂财报与估值口径；不需要懂 RAG 或 prompt 工程。

### 2.2 典型一天

| 时段 | 场景 | 系统行为 | 失败时要知道什么 |
|---|---|---|---|
| 开盘前 | 看自选股行情、跑一次评分 | 实时报价 + 四大师评分 | 哪个指标缺数据（不是「评分 60」而是「评分 60，ROE 缺失」） |
| 盘中 | 问「茅台今天为什么跌」 | 对话 Agent → 工具路由 → 带数据的回答 | 回答里的数字来自哪次取数、哪一期财报 |
| 盘后 | 对一支标的跑深度研究 | 后台管线 1–6 分钟，进度条 | 卡在哪一步；有无章节降级 |
| 读报告 | 判断这个估值能不能用 | 报告含数据说明区块 | DCF 假设哪些是模型推的、分部占比是否为估计、有无插补 |
| 复盘 | 发现某个数字不对 | 点 👎 并说明 | 这条反馈能定位到具体消息与具体版本 |

### 2.3 痛点→需求映射

- 「报告写得挺像，但我不敢直接引用」→ FR-1、FR-3
- 「模型编了个数字，我事后才发现」→ FR-4、FR-8
- 「这块内容空了/假了，报告里看不出来」→ FR-5、FR-6
- 「我不知道这次改动让质量变好还是变差」→ FR-2、FR-11
- 「我提的意见没人接住」→ FR-9、FR-10

### 2.4 非目标人群

投顾对客合规输出、需要 SLA 的生产系统使用者、多用户团队。见 §3.2。

## 3. 范围与非目标

### 3.1 范围内

| 项 | 说明 |
|---|---|
| 事实台账 | 每次管线运行产出带出处的数字清单（五种出处，无第六种） |
| 五层评测 | L0 台账闭合、L1 数值接地、L2 检索质量、L3 生成规则、L4 端到端 |
| 回归基线 | 指标化基线 + 容差 + 漂移告警，作为本地门禁 |
| 降级显式化 | 三处静默兜底改为带 `degraded` 标记 + 报告可见说明 |
| 数据飞轮 | 反馈采集 → 待审队列 → 人工审阅 → （人工决定是否进回归集） |
| 产品文档 | 本 PRD + README 更新 |

### 3.2 非目标（明确不做）

| 不做 | 理由 |
|---|---|
| 多用户 / 权限 / 登录 | 单用户本机运行，鉴权无收益 |
| 部署、容器化、移动端 | 运行环境即开发机 |
| CI / 云端流水线 | L4 需真实 API key，不适合云端定时跑；用 `run_eval.py --baseline` 作本地门禁 |
| 交易执行 / 下单接口 | 系统定位是研究，不碰资金侧 |
| 商业数据源接入 | 全部依赖零 key 源；有缺口就显式标注，不买数据来掩盖 |
| 用 LLM 自由打分做质量评估 | 分数不可复现、无法归因、进不了回归门槛（见 FR-8） |
| 声称「飞轮带来 X% 提升」 | 样本量不足以支撑任何统计结论（见 §6.3） |

### 3.3 硬约束

1. 数据必须来自真实源或真实计算；缺失显式标注 `None` / 「—」。
2. 评测一律离线跑在落盘产物上：可复现、零 token。
3. L4 依赖真实 LLM 与网络，只做一次性基线，不进日常门禁。
4. 本机 Windows 11、单一 Python 解释器、单进程后端 + Streamlit 看板。

## 4. 功能需求

每条需求的「验收」行给出**可执行断言**（断言名与 `data/eval/*_report.json` 中的 `checks[].name` 逐字一致），并附最近一次实测值。断言全绿即需求达成；任一失败即未达成，不允许用「大致满足」结案。

### 4.1 数值可信（L0 / L1）

#### FR-1 每个数字都登记在案
**需求**：任何进入报告的数值，都必须出现在事实台账里，且台账条数与数值叶子数一致；新增字段若未归类出处，评审判失败（防止映射表腐化）。
**验收（L0）**：`台账闭合：事实数 == 数值叶子数`、`无未归类路径`、`path 唯一`、`出处均在五种合法值内` 全部通过，`unknown_count = 0`。
**现状**：L0 **155/156**，`data/artifacts/` 下 13 份产物共 28,034 条事实，`unknown_count = 0`（`data/eval/l0_report.json`，2026-11-06）。唯一失败项是 `0700_HK/20261105T014111.json` 的 `metric 非空且 value 有限`（6 条 NaN：一行空 K 线 + 由它派生的 `current_price` / `current_pe`）；该产物已被后续四次运行取代（最后一次 `20261106T175253`，300 根 K 线、无 NaN），其余 12 份产物的数值均为有限值。失败产物按约定保留在盘上、不被静默跳过（见 FR-4「NaN 不得进产物」）。

#### FR-2 评测结果可复现
**需求**：同一份产物，任何时候评测得到同一个结果；`run_id` 由内容派生，产物变了 id 就变。
**验收（L0）**：`两次构建事实序列一致`、`内容哈希可复算`、`run_id 由内容派生`、`fact_id 唯一`、`fact_id 连续编号` 全部通过。
**现状**：13 份产物 × 上述 5 条断言 = 65 项全通过。

#### FR-3 报告里的数字能追到出处与期间
**需求**：每个数字都要能说出它是代码算的、数据源取的、模型给的还是插补的，以及属于哪一期；财务比率类事实必须带 `as_of`。
**验收（L0）**：`财务比率带期间 as_of`、`降级/插补事实均带 evidence_ref` 全部通过，`as_of_coverage` 达基线水平。
**现状**：`as_of_coverage = 0.9293`、`unit_coverage = 0.8485`（含非期间类事实，故未达 1.0；残差逐条列在 L0 报告中，不以放宽阈值掩盖）。
**说明**：这两个覆盖率**不是**「全部数字都有 as_of」，而是「有期间语义的事实中带了期间的比例」。未达 1.0 的部分逐条可查，不作为已解决项宣称。
**已知缺口**：出处与期间目前只在**台账**里可查，**报告正文没有「数据说明」区块**——读者在报告里看不到「这个毛利率是插补出来的」。报告只对分部占比等少数位置做了文字标注。补法：在报告加一段列出 `imputed` 事实，并新增对应 L3 断言。属报告行为改动，需单独批准，不在本版本范围内。

#### FR-4 模型不得自造数字
**需求**：模型撰写的文字中的数字，必须能在台账（`computed` / `source`）里找到同名同值的对应项；找不到的即「未接地」，需逐条列出。
**验收（L1）**：`接地率 ≥ 0.98`、`反向控制：伪造 99.99% 被检出`、`扫到模型撰写字段（白名单未腐化）`、`模型判断落在合法取值域`、`正向控制：片段里的数被计成 doc_grounded` 全部通过。最后一条是外部语料接入后的正向控制：往产物里塞一个只在检索片段里出现的数，必须被计成 `doc_grounded` 且接地率不降——证明片段正文里的数字真的进了匹配集合，而不是只在台账里自说自话。当前 4 份产物 `doc_facts = 10`、`doc_grounded = 0`（产物生成于外部语料入库之前），控制探针在 2 份含片段数字的产物上全部命中，另 2 份的片段里没有台账之外的数字，控制标记为不适用而非通过。
**度量对象（2026-11-05 收敛）**：分母只算**数值断言**——带单位或百分号、带小数位、带千分位、带货币符号，或处在带单位的区间里。「国窖1573」「茅台1935」「《1974年贸易法》」「HS 8517/8471」这类名称与编码不再是断言；年份统一计入 `year_ref`，期间一致性由 L3 的 `期间一致：年份须在事实期间内` 负责，不在 L1 重复计分。裸整数（不带单位、不带小数与千分位）也不计入，但**仍逐条比对并在报告里列出可解释/无出处数量**——不计入不等于看不见。**时间跨度**（`6 个月内`、`3 年后`、`周左右`）同样不计入，单列为 `time_ref`：它是在讲期限，不是在陈述某个量的值；地缘分析里的「6 个月」本就来自提示词给出的 `date_6m` 视野。此规则只在整数后接 `内/后/之后/以后/左右` 时生效，`5 年 CAGR`、`30 日均线`、`6 亿` 照旧算断言。

**派生值：只认文本锚定的复算**。模型会把「2022 年 20.5% → 2025 年 33.1%」写成「三年扩张 1260bp」。纯按值复算**不可用**（见下），但文本锚定的可以。成立条件三条缺一不可：① 同一句里出现指标名（毛利率/净利率/营业利润率/ROE/流动比率…）；② 同一句里出现两个不同年度；③ 台账里该指标在这两期都有事实，且差值按显示位数对得上。另有补充规则：**同句两个已接地数字之差**（覆盖「从 34.0% 骤降至 19.4%（-1460bp）」这种只写一个年份、另一端隐含的写法）。

**现状（2026-11-06 第二轮重采后复测，已达标）**：L1 **22/22 通过，聚合接地率 0.9952**（208 条数值断言，207 条接地，1 条未接地；文本锚定复算命中 0 条——提示词禁止写区间与倍数后，模型不再构造派生数字）。208 条按标的分布：000858.SZ 37、600519.SS 83、AAPL 86、0700.HK 2。

| 标的 | 接地率 | 未接地数字 |
|---|---|---|
| 000858.SZ | **1.0**（37/37） | — |
| 600519.SS | **0.988**（82/83） | `98.2`：产物生成于集中度修复之前，仍引用旧口径的 CR3（已知残差，未过阈值的余量内） |
| AAPL | **1.0**（86/86） | — |
| 0700.HK | **1.0**（2/2） | — |

**宏观利率这一条是怎么修的（2026-11-06）**。此前的 0700.HK 残差不是模型幻觉：`MASTER_SYSTEM_PROMPT` 里写死了「高利率（4.4%）」「美国基准利率 4.25-4.50%」「4.5% 无风险利率」，模型忠实照抄，台账里自然没有这个数。这条提示词在 swot / competitive / geopolitical / segment 四个模块各存一份、逐字节相同。修法两条：

1. **提示词去数字化**：四份合并为 `app/analysis/master_prompt.py`，利率改为运行时占位符。真实利率由 `estimates.get_risk_free_rate()` 从**美国财政部官方每日收益率曲线 10Y** 取（本机实测可达；不可达时回落 akshare 汇总的美国 10 年期，两条都失败才用常量兜底）。港股按港币联系汇率以美元利率近似，并在备注里写明这是近似。
2. **拿不到真值就不给数**：低置信度的兜底常量不再喂给模型，占位符换成「无风险利率数据当前不可用，禁止写出任何具体利率数值或区间」——缺数据退化成定性表述，而不是逼模型猜一个数。数值纪律同步新增第 6 条。

重采后产物里的 `risk_free_rate` 为 `0.0484`（US Treasury 10 Yr，观测日 2026-11-05），模型在威胁段落写「无风险利率 4.84%」并把来源标成 `US Treasury 每日收益率曲线 10 Yr（官方）`，两条断言全部接地。**机制验证**：同一台账下写 `4.84%` 命中断言、写 `4.4%` 仍然不命中——修的是「产物里那条数是不是真的」，不是放宽匹配。

**0700.HK 判定为已知残差、不放松阈值**：该标的历次实测都低于 0.98（非降级产物 47/48 = 0.9792、降级产物 34/36 = 0.9444、重采产物 0/2）。残差形态在变——从照抄「4.25–4.50%」区间，到取中点写「4.4%」——但根因同一条：**模型在引用外部宏观基准，而台账里不可能有这类事实**。它不属于公司事实，治法是改提示词禁止引用外部基准，本轮**保留并登记**，不靠放宽匹配规则凑绿。比率 0.0 不是「比 0.9444 更糟的质量信号」，而是小分母：整份产物只有 2 条数值断言且都栽在同一个数上。要判断质量得看绝对条数（2 条未接地，与此前的 2 条持平）。

**非断言部分（不计入分母，但仍逐条比对）**：53 个裸整数中 49 个能被台账解释、4 个无出处，逐条列在 `non_claim_samples` / `non_claim_misses`；134 个年份 token 计入 `year_ref`。

**产物选择口径**：每标的只取**时间戳最新**的一份产物计分。历史产物保留在磁盘上不删除，被排除的名单逐份列在报告的 `skipped_superseded` 里——评测测的是当前系统，但被跳过的文件不静默消失。

**指标口径的三处修正（2026-11-05）**：
1. **NaN 不得进产物**：源在当日 K 线未成交时整行 NaN，`math.floor(nan)` 会让匹配器崩溃，且 `pe_percentile` 会算成假的 `0.0`。修在源头（`pipeline` 剔除非有限 K 线、`financial` 取最近一个有效收盘、样本不足返回 `None`），并在匹配器加兜底：非有限值不参与匹配。
2. **没有真分母就不出集中度**：CR3/CR5/HHI 若以「标的 + 已知同业」作分母，5 家就必然 CR5 ≡ 100%——数是真的，口径是假的。现在**缺行业总规模时三者返回 `None` 并给出原因**，份额改称「已知同业样本内份额」。
3. **浮点噪声不能当接地依据**：`cr5 = 0.9999999999999999` 显示成「99.99」，足以让一条伪造的 99.99% 蒙过反向控制。上述第 2 条直接从根上消除了这个假接地来源。

**复算规则的两轮验证**：
1. **纯按值复算 → 否决**：「CR3 98.2%」被凑成流动比率 2010−2019 的差、「600 元」被凑成 ROE 2003−2017 的差、「150–250bp」被凑成毛利率 2021−2023 的差。只看数值不认指标，等于给编造发通行证，代码已回退，否决记录留在 `grounding.py`。
2. **文本锚定 → 采纳**：历史产物上三条复算结果与原文语义一致（`1260bp` = 营业利润率 2025 − 2022；`330bp` = 毛利率 2024 − 2025；`1460bp` = 同句 34.0 − 19.4）；`verify_evals.py` 用 7 条断言锁住边界（有指标名+两期才认、无指标名不认、差值不符不认、指标不同不认、端点未接地不认）。
反向控制（伪造 99.99%）在本轮每份参与计分的产物上都仍被检出。
**阈值为何不是 1.0**：中文里数字与名称、区间、序号高度混叠，强行 1.0 只能靠放宽匹配规则（例如不判符号、按显示位数比对）来凑，反而掩盖问题。保留 0.98 + 逐条残差可见，比 1.0 的假绿更有信息量。

#### FR-5 降级必须显式且可解释
**需求**：模块失败时不得静默返回看似正常的默认值。降级与插补事实必须带 `evidence_ref`，说明为什么降级。
**验收（L0）**：`降级/插补事实均带 evidence_ref` 全部通过；`degraded_rate` 与 `imputed_rate` 在指标中可见。
**现状**：`degraded_rate = 0.0009`（28,034 条中 25 条）、`imputed_rate = 0.0114`（320 条），全部带 `evidence_ref`。

#### FR-6 缺失值不得渲染成假数
**需求**：缺数据时报告显示「—」或标注「未生成」，不得填入默认值、不得留白、不得用 0 冒充。
**验收（L0 + L3）**：`metric 非空且 value 有限`（无 NaN/Inf）与 `无空章节` 全部通过；缺失值渲染为「—」由 `app/report/markdown.py` 与 `app/data/cleaning/missing_handler.py` 的显式标注保证，`scripts/verify_trust.py` 37/37 覆盖。
**现状**：全通过。
**未覆盖的一处**：分部降级导致 SOTP 整块不出数时，报告跳过该区块且不显示原因。`无空章节` 检查的是已渲染章节，管不到「整块缺失」。该缺口登记于 §8.1，本版本不修。

### 4.2 质量评测（L2 / L3）

#### FR-7 检索质量可度量且有基线
**需求**：知识库检索质量以 nDCG@k / Recall@k / MRR 度量，标注必须来自人工，不得代编；召回率需注明其估计口径。
**验收（L2）**：`nDCG@4 ≥ 0.5（人工标注集）` 通过，且报告带 `labels = human`。
**现状**：25 条查询 × 6 篇 = 150 条人工判断（项目作者标注），**nDCG@4 = 0.9461**、**Recall@4 = 0.8813**、**MRR = 0.96**，漏召回 3 篇。
**口径**：语料为冻结的只读快照 `data/knowledge_db_v1`（**2,041 切片**：1,907 研报切片自入库 + 100 条东财宏观快讯 + 12 条宏观数据 + 20 条个股新闻 + 公告/股东大会各 1 条），**不是外部权威语料**；外部语料（政策/披露文件/论文）只进正式库、不入 v1，故本基线不受其影响。召回率为池化下界估计（标注池 = top-4 + 盲抽 2 篇），真实召回率不会低于该值。这两条限制写在 `l2_report.json` 的 `note` 里，不得在对外表述中省略。

#### FR-8 报告生成有硬规则，不用自由打分
**需求**：生成质量用确定性规则判定，每条规则失败时能指出「哪份产物、哪一行」。不使用「请给 1–10 分」式 LLM 打分。
**验收（L3）**：以下 8 条规则在全部产物上通过：`期间一致：年份须在事实期间内`、`情景推演已标注（非事实陈述）`、`竞品真实：名称须来自数据源`、`敏感性单调：折现率↑估值↓`、`分部占比自洽且已标注`、`措辞红线：无确定性承诺`、`无空章节`、`红队引用可核对：反方论证必须有 evidence_ref`。
**现状**：**13 份产物 × 8 条 = 104/104**。第 8 条于 2026-11-06 加入：红队（deep 档才有）提出的每条反方论证都必须指向本产物事实池里真实存在的一条，引用对不上就整条丢弃、不许留在产物里——否则红队会变成第二个幻觉源。现有 12 份产物都不带 `redteam` 字段，该条以「无红队段落」直接通过，因此 L3 数字变化只来自规则条数与产物份数，不来自产物内容。此前记为「7 份 × 7 = 49/49」「11 份 × 8 = 88/88」，分别是产物增到 11、12 份之前的值。产物增加后本层一度整体中断，原因在两处渲染缺陷：① `dcf.fair_value` 有值但 `upside` 为空时，摘要行仍执行 `None * 100`；② SOTP 有分部但算不出每股区间（缺现价）时，整张分部表连同「分部占比为模型估计」的声明被一起跳过。两处于 2026-11-06 修复：缺失值标 `—` 而不是崩，标注与 per-share 解耦。修复后 12 份全通过。

### 4.3 飞轮与观测（P5）

#### FR-9 反馈可归因
**需求**：用户对一条回答/一份报告的 👍 / 👎 必须能定位到具体消息与具体版本（模型、提示词版本、代码版本）。缺关联键的反馈不允许入库（否则是孤儿数据）。

**现状**：机制已接通，**当前 0 条真实反馈**（联调用的测试数据已删除，不以测试数据冒充真实反馈）。

#### FR-10 护栏指标可见

### 4.4 交付与门禁（L4 / 基线）

#### FR-11 评测必须会失败
**需求**：门禁的价值在于能报警。需有专门脚本构造坏数据，证明接地反向控制、基线漂移、L3 各条断言都会触发失败。
**验收（门禁）**：`scripts/verify_evals.py` 112/112 通过（新增 6 条：角色指令模板不再写死宏观利率、真实利率渲染进提示词、低置信兜底不喂数、港股注明近似、共用指令计入 prompt_version、时间跨度不算断言的双向边界；另 7 条锁住构成比门控：集合未变时构成比下滑仍报警、跳过构成比后不再报该指标、跳过不影响质量指标与层状态受保护、同一产物内容变不算集合变动、新增产物算变动并点名、老基线无指纹按未变动处理）；`run_eval.py --baseline` 在指标掉出容差、整层状态由 PASS 退步、或出现基线未记录的新失败项时退出码非 0 并指明层与指标。
**现状**：通过；`RATIO_METRICS`（nDCG/recall/MRR）已纳入门禁保护。基线于 2026-11-06 按当时 11 份产物重录，文件内的 `known_reds` 如实记下建基线时即存在的 L0/L1 两条已知红（0700_HK 的 6 个 NaN 与接地率未达标），使「基线本来如此」与「有人把失败录成基线」可区分。门禁退出码只看**变化**：已知红不再把退出码永久钉死，新增失败项仍会报警。

**已知红的比对键（2026-11-06 修）**：L1 每标的只评最新一份产物，重采一次文件名就变，按文件名比会把这个标的的同一个老毛病当成新红，于是每次重采都得重录基线。现改为 L1 按**标的目录**比、L0 按**文件名**比——L0 评的是全部产物，按目录比会让同标的的第二份产物被前一份的已知红遮住。`verify_evals.py` 用两条反向用例钉住这两种行为。

**反向控制的判定（2026-11-06 修）**：原判据是「注入 99.99% 后接地率必须下降」，分母极小时（整份产物只有 2 条断言且都未接地）比率恒为 0，注入伪造值也不会更低，于是把「匹配器真的接住了 99.99」这个真问题误报成「控制失效」。现判「未接地**条数**是否变多」，比只看比率严格：伪造值被漏接时条数一定增加，被误接时条数不变、照样报警。

#### FR-12 端到端可用（一次性基线）
**需求**：三支真实标的（沪市高毛利、深市、美股各一）跑完整管线，记录成功/降级/token/耗时。该基线一次性执行，不进日常门禁。
**验收（L4）**：`全链路成功 3/3`、`降级均可解释`、`台账闭合（L4 产物复跑 L0）`、`耗时与 token 完整记录` 全部通过。
**现状**：4/4 通过（2026-11-05）。三支全部成功，事实数 2663 / 2709 / 2713，台账 12/12 闭合，耗时 221.2 / 261.1 / 85.1 s。
**判据变更记录（判据 v1 → v2）**：v1 要求「降级事实为 0」。首次真实基线证明该门槛**结构上不可达**——4 条降级全部来自零 key 源的覆盖缺口（A 股无股东大会数据 → `meeting_count`；AAPL 无新闻/公告 → `article_count` / `briefing_count`），系统正确地没有把「查不到」渲染成 0。v2 改为「降级均可解释」：每条降级事实必须带 `evidence_ref` 且路径可定位，降级数量与明细照常记录。**这是判定标准的变化，不是实测数据的变化**：`l4_report.json` 里的耗时与 token 原样保留，并用 `criterion_version` / `rescored_at` 标注重判时间，可追溯。

## 5. 非功能需求

### 5.1 延迟

**L4 一次性基线实测（墙钟，2026-11-05）**：

| 标的 | 墙钟 | 管线自报 | 事实数 |
|---|---|---|---|
| 600519.SS（沪市） | 221.2 s | 221.1 s | 2663 |
| 000858.SZ（深市） | 261.1 s | 261.1 s | 2709 |
| AAPL（美股） | 85.1 s | 85.1 s | 2713 |

历史产物（管线自报，2026-11-04）：600519.SS 355.34 s、AAPL 79.67 / 85.18 s、0700.HK 75.55 s。

- A 股明显慢于美股/港股：同一管线、不同取数通路与源站限速，不是代码分支差异。
- 计划书里「深度研究 ~140–160s」的旧估计与本机实测不符，以本表为准。
- 同标的两次耗时差异可达 60%（600519.SS 355 s → 221 s），主要来自源站响应波动；因此延迟只能给区间，不能给承诺值。
- 用户可见要求：超过 60 s 的路径必须显示进度，不允许无反馈等待。

### 5.2 成本

L4 实测 token（2026-11-05，每支标的 6 次 LLM 调用）：

| 标的 | tokens_in | tokens_out |
|---|---|---|
| 600519.SS | 2129 | 5778 |
| 000858.SZ | 7978 | 5523 |
| AAPL | 3353 | 5600 |
| **合计** | **13460** | **16901** |

- 结构特征：输出 token 与输入 token 同量级（约 1.26:1），研究型任务的成本重心在**生成**而非检索。
- 输入 token 波动大（2129 ~ 7978），取决于取到的财报期间数与竞品数量——标的越复杂，注入上下文越长。
- **不给价格数字**：模型定价随时调整，写死即过期。要算成本，用当时的实际单价乘上表 token 数即可。
- 口径限制：这是本机单次运行的计数，含重试；换模型或改提示词后需重测。

### 5.3 可用性

- 无 SLA，单机单进程。可用性由「失败可见」保证，而非「失败不发生」：数据源失败必须落到显式降级，不得静默返回假数据。
- 离线评测层（L0–L3）不依赖网络与 LLM，随时可跑。

### 5.4 可复现性

- 同一产物 → 同一评测结果（L0 断言 `两次构建事实序列一致` 保证）。
- 检索评测的定序问题已修：同分边界按 `(分数, id)` 定序，稀疏乘锁单线程（`threadpoolctl`），避免 BLAS 累加顺序导致结果漂移。

### 5.5 容量

知识库分两套：正式库 `data/knowledge_db` **22,943 切片**（研报 2,090 + 披露文件 13,504 + 论文 6,186 + 政策 1,029 + 宏观新闻 100 + 宏观数据 12 + 个股新闻 20 + 公告 1 + 股东大会 1）；L2 固定跑只读快照 `data/knowledge_db_v1` **2,041 切片**（1,907 研报 + 100 宏观快讯 + 12 宏观数据 + 22 个股新闻/公告），外部语料不入该快照。单次产物 16 个 section；L0 与 L3 都覆盖 `data/artifacts/` 下全部 **11 份产物**（L0 计 24,877 条事实，约 2262 条/份；L3 计 88 条规则断言）。L2 只跑 v1 快照——基线是在快照上标的，拿正式库跑等于换考题（2 万余条外部切片会把标注里的相关文档挤出 top-4），故 `run_eval.py` 的 l2 档固定读 `l2_v1.lock.json` 指向的快照，快照缺失时打印警告而非静默降级。超出该量级需重新评估评测耗时：L0–L3 全量本机实测 **约 47s**（2026-11-06，11 份产物，含嵌入模型加载）。

## 6. 指标体系

### 6.1 北极星：有效研究产出数

**定义**：落盘且未被标注为「整份报告有问题」的研报份数。

- 分子：`data/reports/` 中的研报数 − 收到 `scope = report` 且 `label = down` 的唯一报告数。
- 当前：研报 70 份 PDF，反馈 0 条 → 北极星 = 70。
- **诚实说明**：这个数在反馈积累起来之前几乎等于「生成了多少份报告」，不度量质量。它作为北极星是因为它是唯一能被真实采集、且指向「用户是否拿到可用结论」的指标；在样本量起来之前，它的解读必须以护栏指标为约束。

### 6.2 五个护栏

| 指标 | 口径 | 当前值 | 分母为 0 时 |
|---|---|---|---|
| `grounding_rate` | 离线 L1 评测（跑在落盘产物上，每标的取最新一份） | 0.9952（4/4 产物达标，见 FR-4） | 显示「—」 |
| `degraded_rate` | 离线 L0 评测 | 0.0009 | 显示「—」 |
| `llm_error_rate` | 进程内计数（重启清零） | None（后端未跑） | 显示「—」 |
| `feedback_negative_rate` | `feedback.db` 全库 | None（0 条反馈） | 显示「—」 |
| `feedback_coverage` | 有反馈的回复 / 全部助手回复 | 0.0 | 显示「—」 |

前两项是质量护栏，后三项是飞轮健康度。**离线值与实时值不可混为一谈**：`/api/v1/metrics` 的 `meta` 字段对每项标注 `scope` 与 `as_of`。

### 6.3 不声称的结论

- 不声称「飞轮带来了 X% 提升」：单用户、样本个位数量级，无法支撑统计结论。
- 不声称 L2 指标代表生产检索质量：语料为自生成研报，查询与文档同分布，指标偏高。
- 不声称「零幻觉」：L1 是「数字可归因率」，L3 是「规则通过率」，二者联合起来排除了一批具体失败模式，不等于证明不存在幻觉。

## 7. 数据与埋点

### 7.1 三张表 + 一个待审队列

| 位置 | 写入方式 | 关键字段 |
|---|---|---|
| `data/audit.db` `audit_log` | 只追加 | `request_id`、`event_type`、`detail_json`、`model`、`prompt_version`、`git_sha` |
| `data/memory.db` `conversations` | 只追加 | `msg_id`、`role`、`content`、版本戳三件套 |
| `data/feedback.db` `feedback` | 只追加，无 UPDATE/DELETE | 12 列：`id, ts, request_id, msg_id, label, scope, fact_id, options_json, note, model, prompt_version, git_sha` |
| `data/flywheel/inbox.jsonl` | 只追加 | 👎 记录的镜像，`status = pending_review`、`promoted = false` |

### 7.2 最小字段集与关联键

- 反馈能归因的唯一钥匙是 `request_id` + `msg_id`；两者任一为空，接口返回 422。
- 版本戳由服务端打戳，客户端提交的 `model` / `prompt_version` / `git_sha` 一律忽略（防止伪造归因）。
- `prompt_version` 是提示词常量所在模块源码的哈希（形如 `p` + 8 位十六进制），改提示词自动变化，无需手工 bump。

### 7.3 隐私与留存

- 全部数据存本机 SQLite / JSONL，不上传第三方；唯一外发内容是发给 LLM 的提示词与上下文。
- 不采集：账户信息、设备指纹、位置。上传的附件仅在本地 OCR/转写，识别结果随对话存在 `conversations`。
- 留存：不自动删除（审计与评测需要历史）。清除需人工操作，且属于不可逆动作。

### 7.4 防污染规则

👎 反馈**绝不自动进入回归集**。一次误操作若能把错误答案固化成金标准，飞轮会自我污染。进回归集必须是人工 promote，且当前版本不提供自动 promote 代码路径。

## 8. 风险与降级

### 8.1 三处曾被伪装的降级

| 位置 | 旧行为（缺口 3） | 现行为 |
|---|---|---|
| `swot.py` | LLM 失败返回 `rating = 中性`，报告照常渲染成「SWOT 综合评级」 | 严格模式下 `rating = None` + `degraded: true` + `reason`；报告渲染为「**SWOT 综合评级**: 未生成（原因）」 |
| `segment.py` | 失败返回 100% 占比的「综合业务」，并进入 `compute_sotp()` 参与估值 | 占位分部带 `degraded` + `reason`；`compute_sotp()` 见降级分部即不输出 SOTP 数值（`per_share_* = None`），并给出 `reason` |
| `news.py` | LLM 失败仍置 `available = True` | 置 `analysis_degraded = True` + `reason`（刻意不用 `degraded` 键，避免把真实的文章计数一起标成降级）；报告渲染为「暂无新闻/公告舆情分析。（原因）」 |

**已知缺口（未修复，如实登记）**：分部降级导致 SOTP 不输出时，报告直接跳过 SOTP 区块，`sotp_analysis.reason` **当前不在报告中显示**——读者只会看到「没有 SOTP」，看不到「为什么没有」。L3 的 `无空章节` 只检查已渲染的章节，覆盖不到「整块缺失」。补法有两条：渲染一行「SOTP 未生成（原因）」并新增对应 L3 断言。这属于报告行为改动，需单独批准，不在本版本范围内。

共同根因是 `parse_llm_json` 解析失败只写日志、调用方拿不到「我降级了」的信号；本版本把该信号一路带到产物与报告。

### 8.2 外部数据源失效路径

| yfinance（全球） | 字段 `None`，不插补行情 |
| 东财 F10（美股财务） | 财务区块标注缺失，DCF 不生成而非套用默认值 |
| 天天基金（净值） | 返回缺失 + 取数时间，不作为最新净值展示 |
| SEC EDGAR | 过期 CIK 不缓存 24h；UA 使用声明性字符串（浏览器 UA 会被 403） |
| US Treasury / FOMC | 曲线/声明不可得时，利率模块显式标注不可用，不给默认曲线 |

这两条覆盖缺口是 L4 首次基线里唯一的 4 条降级事实，也是判据 v1「降级 0」不可达的直接原因。

**发布判定**：L0–L3 全绿 + L4 一次性基线通过 + 本 PRD 的 FR↔断言双向映射无缺口。

**当前判定：未通过。** L0 **155/156**、L1 **22/22（已全绿）**、L2 1/1、L3 **104/104**、L4 4/4（判据 v2）。唯一未达标项是 L0 里保留在盘上的历史产物 `0700_HK/20261105T014111.json`（那行 NaN，见 FR-1），按约定不删、不静默跳过，故 L0 不是全绿。L1 从 21/22 转为全绿的原因写在 FR-4：残差不是模型幻觉，而是提示词里写死的「4.4% / 4.25–4.50%」被模型忠实引用；把提示词去数字化、并把真实无风险利率接上美国财政部官方曲线后，0700.HK 的两条断言全部接地（1.0），同一台账下写 `4.4%` 仍不命中——不是放宽匹配换来的绿。

**门禁的构成比噪声（已修，2026-11-06）**：`run_eval.py --baseline` 曾在产物集合发生变化（新增一次采集）时报 `computed_rate` 下滑。这是**构成比**：五个出处占比恒加起来为 1，新增产物带 1500+ 条 source 事实，即使每条出处都正确，比例也会被稀释（基线 12 份产物 → 现 13 份，`computed_rate` 0.3062 → 0.2752）。逐份检查全部通过（`unknown_count = 0`、每份产物出处闭合），所以它不是质量退化，而是这个指标不适合跨语料比较。修法是**按产物集合门控**：`_artifact_set_delta()` 用路径集合（不认内容指纹——同一批产物里某个数变真，分母没变，构成比照样可比）判断集合是否变动，变动时 `_compare()` 跳过五个构成比并打印跳过清单与增删份数。**不是静默放过**：逐产物检查（`new_reds`）与 `unknown_count`（`MUST_NOT_GROW`）照旧比对；产物集合一致时构成比仍参与门禁，`grounding_rate`、`mean_ndcg` 等质量指标从不跳过。未重录基线。

## 附录 B　术语

| 术语 | 含义 |
|---|---|
| 事实台账 / ledger | 一次管线运行产出的带出处数字清单，`fact_id` 连续编号 |
